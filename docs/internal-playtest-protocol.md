# 内部试玩协议：最快可玩桌面版本

版本：`0.1.0-dev`  
用途：验证当前灰盒运行时是否可玩、可重复、值得进入最终资产生产；不是商店发布验收。

当前交付形态包括 Godot 源码试玩入口和 Windows x86_64 内部构建；源码入口适合最快开始内部测试，Windows 构建仍未完成 Windows 10/11 目标设备回归，不能替代正式发布验收。

## 无鼠标候选回放入口

如果研发过程中不希望占用鼠标、键盘或前台窗口，使用：

```text
npm run playtest:candidate:full:headless
```

该入口只执行候选资源导入预热、办公室与城市集成回放、音频契约、任务/镜头/NPC/载具/存档检查和候选包验证，不启动图形窗口；它不会生成视觉通过结论。需要真实画面时，必须另行使用 Windows 目标设备或已确认可用的图形采集会话，并重新完成逐段人工验收。

`npm run playtest:candidate:full` 是交互式图形试玩入口，可能创建 Godot 窗口；无鼠标研发时不要使用该入口。

## 1. 启动

在工作区根目录执行：

```text
npm run playtest:desktop
```

第一轮只验证办公室时可以直接执行：

```text
npm run playtest:office
```

需要复测城市载具和存档时执行：

```text
npm run playtest:city
```

选择入口：

- `准点下班`：优先试玩，覆盖第三人称移动、蹲伏、NPC 感知、交互、失败、重试和存档。
- `中国街区任务`：第二轮试玩，覆盖物品、冲突、三轮车、城市任务和城市存档。

## 2. 第一轮：办公室 10 分钟闭环

1. 从入口进入“准点下班”。
2. 用 `WASD` 移动，方向键或鼠标控制镜头，按 `C` 蹲伏。
3. 观察上司和巡查 NPC 的视野，尝试从工位和隔断后绕行。
4. 到达电梯/出口并按 `E` 交互。
5. 至少故意触发一次发现和失败，按 `R` 重试。
6. 完成一次成功路线，再按 `L` 验证检查点读取。
7. 暂停、继续、重启当前场景，确认任务没有重复推进或状态丢失。

记录以下结果：

```text
是否在 30 秒内理解目标：
移动/镜头是否可控：
蹲伏是否改变风险：
NPC 发现是否可理解：
失败原因是否清楚：
重试是否可重复：
读取存档后状态是否正确：
最影响体验的问题：
```

## 3. 第二轮：城市 10 分钟闭环

1. 从入口进入“中国街区任务”。
2. 进入店铺并完成物品交互，确认库存和任务目标同步变化。
3. 触发一次冲突，观察人群位移和任务状态。
4. 找到三轮车，测试 `V` 上下车、驾驶、碰撞和退出。
5. 到登记点完成交互，再读取城市检查点。
6. 暂停、重启和返回入口，确认城市实体不会重复生成或残留。

## 4. 问题分类

- `P0 可玩性阻断`：无法启动、无法移动、任务无法完成、失败后无法重试、存档损坏。
- `P1 行为问题`：NPC 状态错误、交互条件错误、载具状态错误、回放不可重复。
- `P2 表现问题`：镜头构图、动画、HUD、音频或灰盒外观与参考不一致。
- `P3 最终资产问题`：角色、环境、材质、灯光、招牌、道具和音频需要原创生产。

## 5. 试玩结论门

只有以下条件同时满足，才进入最终资产生产：

- 办公室任务能从开始玩到成功或失败并重试。
- 城市任务能完成一条物品/冲突/载具流程。
- 没有 P0 问题。
- P1 问题已经有明确修复任务和回放证据。
- 试玩者能说清楚目标、风险和失败原因。

视觉与参考视频的相似度仍单独走 `docs/visual-acceptance-tool.md` 的逐帧签收流程，不能用试玩“感觉不错”替代。
