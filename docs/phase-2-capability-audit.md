## 3. 基准测试必须通过的能力

### 角色和镜头

- 八方向移动、停止、转身和碰撞行为可重复。
- 镜头跟随距离、俯仰角、转向速度可配置。
- 角色被遮挡时镜头不会穿墙或丢失目标。
- 键鼠、手柄和触屏输入都经过同一套输入抽象层。

### NPC 感知

- 视野角、距离、遮挡和警觉增长可配置。
- NPC 从未知、怀疑、发现、追踪、丢失到恢复的状态可记录。
- 相同输入和相同随机种子下，NPC结果必须一致。
- NPC状态必须能够被任务系统和回放系统读取。

### 任务状态机

- 任务目标、前置条件、完成条件、失败条件和重试入口分离。
- 任务状态支持保存和恢复。
- HUD只读取任务状态，不自行修改任务逻辑。
- 任何任务都可以输出完整状态时间轴。

### 载具

- 上车、下车、驾驶、碰撞和任务交接分别测试。
- 默认车辆物理只作为第一轮可玩性验证。
- 如果无法复现视频中的转向、速度和停车行为，必须替换为自定义车辆控制层。

## 5. 建议的实际执行顺序

1. 已在当前独立 Godot 项目目录初始化本地 Git 仓库；仍需建立首个基线提交，不把旧目录内容混入发布分支。
2. 锁定 Godot 版本和目标设备清单。
3. 只导入一个原创灰盒场景，不导入受限第三方资产。
4. 完成角色、镜头、NPC感知和任务状态机四项基准能力。
5. 用“准点下班”验证逻辑还原。
6. 用“免费鸡蛋”验证城市、载具和任务扩展。
7. 两个场景都通过后，再建立美术、音频和城市内容管线。

## 6. 当前阶段的禁止事项

- 不下载或复制 Rockstar 相关资产、地图、角色、声音或商标。
- 不把第三方演示项目直接改名作为商业产品。
- 不用假按钮、假 NPC、假车辆或静态录像替代真实系统。
- 不在没有逐帧证据的情况下声称“100%还原”。
- 不把当前灰盒工程误标为最终上架版本，正式资产和平台导出仍需独立门禁。
