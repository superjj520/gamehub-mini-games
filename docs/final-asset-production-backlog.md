| 商业权利 | 参考视频 `confirmed_denied`（不进发布包） | 参考视频仅用于研发、抽帧、对照和内部优化；最终资产必须另行登记原创来源或商业许可 |

## 3. 推荐生产顺序

### 阶段 A：锁定可玩基线

目标是让所有最终资产替换都有稳定的运行时接口，避免先做美术、后返工逻辑。

1. 保持办公室任务、城市任务、载具、存档、暂停、失败/重试和扩展街区的自动化测试通过。
2. 以 `docs/asset-production-manifest.json` 的 8 个槽位为唯一生产清单，不新增未经评审的资产类别。
3. 每个槽位先建立尺寸探针、原点、碰撞体、挂点和动画命名检查。
4. 保留当前灰盒截图作为结构基准，不把它们误标为最终视觉通过。

出口：`npm run test:reference`、`npm run verify:evidence-binding`、`npm run verify:asset-delivery` 全部通过。

### 阶段 B：先做高影响资产

优先处理决定画面是否“像一款游戏”的资产，而不是先做小道具。

| 优先级 | 资产槽位 | 首批内容 | 必须覆盖的扩展状态 |
|---|---|---|---|
| P0 | `player-character` | [原创玩家四视图参考板](../art-source/characters/player-design/new-era-awakener-player-turnaround-v1-generated.png)、主角外观、站立/行走/蹲伏/交互/受击/失败动画 | 办公室近景、城市奔跑、载具上下车 |
| P0 | `city-environment-kit` | 店铺立面、道路、路缘、街灯、仓储门头、装卸点、天气材质 | 后场仓储、白天/黄昏/雨后 |
| P0 | `three-wheel-vehicle` | 车体、车轮、驾驶位、碰撞反馈、损伤材质 | 加速、碰撞、减速、耐久 HUD、失败提示 |
| P1 | `office-environment-kit` | 工位、隔断、门、走廊、电梯厅、楼层牌、呼叫面板 | 追踪、失败、检查点恢复、暂停覆盖 |
| P1 | `office-npc-set` | [原创办公室 NPC 四视图参考板](../art-source/characters/office-npc-design/new-era-awakener-office-npc-turnaround-v1-generated.png)、上司/巡查 NPC、警觉/搜索/恢复巡查动画 | 视野、最后目击点、近景冲突 |
| P1 | `city-crowd-set` | 服装/体型/动作变体、近景和远景 LOD | 入口拥挤、街道分层、交通近失 |
| P2 | `interaction-props` | 鸡蛋、货架、扫码牌、登记员工作点、原创店铺标识 | 领取、扫码、交付、奖励反馈 |
| P2 | `final-audio-library` | 交互、感知、冲突、车辆、环境和失败音频 | 静音备用反馈、设置保存、目标设备混音 |

### 阶段 C：逐槽位接入与验收

每一个资产槽位都必须经过以下 7 个步骤，不能只把文件复制进项目：

1. 记录来源、许可证、生成工具和商业使用范围。
2. 完成单位、朝向、原点、骨骼/挂点和碰撞检查。
3. 在办公室和城市各做一次真实运行时接入。
4. 用固定镜头重新采集对应参考分段和扩展分段。
5. 回放行为轨迹，确认资产替换没有改变任务状态、碰撞、感知和存档结果。
6. 在确认的目标设备上采集帧率、内存、加载和分辨率证据。
7. 由人工逐项完成视觉签收；未签收继续保持 `unverified`，不得伪装成通过。

## 4. 扩展视觉的验收定义

扩展内容不是“多放几栋建筑”，而是必须让玩家在画面中读懂状态：

| 扩展项 | 玩家必须读懂的内容 | 最低验收证据 |
|---|---|---|
| 后场仓储街区 | 这里是可进入的新区域，有仓储入口、装卸点和新的地标 | 入口前后截图、进入轨迹、地标近景、性能报告 |
| 时间/天气 | 当前是白天、黄昏或雨后；地面、天空、角色和室内外光照相互一致 | 三套固定镜头截图、切换事件、灯光/材质检查、性能报告 |
| 载具损伤反馈 | 玩家知道发生碰撞、车辆受损、何时失败以及下一步怎么做 | 碰撞前后截图、车辆轨迹、耐久 HUD、失败反馈和音频证据 |
| 任务收束 | 玩家知道到达、交付、奖励结算和街区状态变化已经完成 | 交付前后截图、任务轨迹、库存变化和奖励反馈 |
| 失败/重试 | 玩家知道失败原因、场景被冻结，并能明确重试或返回 | 失败截图、输入轨迹、重试后首帧、存档一致性证据 |

## 6. 当前不可提前承诺的内容

- 不能把两段 AI 视频直接作为商业游戏内贴图、商店宣传片或最终资产；当前仅按研发参考和内部优化处理。
- 不能在未确认平台前承诺手机帧率、包体、触控布局或 Steam 商店配置。
- 不能用灰盒截图证明“100% 还原”；目前只能证明行为框架、镜头采集链路和差异登记已经建立。
- 不能在未完成最终资产权利记录和目标设备验收前生成“可上架”结论。
