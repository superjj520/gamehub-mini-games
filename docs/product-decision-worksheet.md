## 推荐默认值

如果目标是“尽快得到可玩版本，同时保留接近参考视频的视觉质量”，建议直接确认这一组：

```text
产品名：新时代觉醒者
内部测试平台：桌面源码试玩
正式首发平台：Steam Windows
首发设备：Windows 10/11，1080p，键鼠；手柄作为第二输入验证
首发地区与语言：中国大陆 / 简体中文
首发范围：office_vertical_slice
视觉方向：原创写实，中等细节
版权边界：original_assets_only
参考视频商业用途：仅用于研发、抽帧、对照和内部优化，不直接放入游戏或商店
商业化：首发免费测试版，不接真实支付
预算：单人开发，以 20–35 人周作为办公室垂直切片估算区间
目标上线窗口：先完成内部可玩测试，再决定公开测试日期
```

## 需要用户明确的字段

| 字段 | 推荐值 | 确认后解除的阻断 |
|---|---|---|
| 产品名 | 新时代觉醒者 | 品牌和商店文案可以开始准备 |
| 正式平台 | Steam Windows | 可以建立导出预设、输入矩阵和目标设备 QA |
| 首发范围 | `office_vertical_slice` | 只对办公室 10 段和 6 个资产槽位做首发验收 |
| 视觉方向 | 原创写实，中等细节 | 可以开始 P0 成品角色、办公室环境和动画生产 |
| 地区/语言 | 中国大陆 / 简体中文 | 可以冻结 UI、字幕、商店元数据范围 |
| 商业化 | 免费测试版 | 暂不引入支付、账号和复杂经济系统 |
| 预算/人周 | 20–35 人周 | 可以建立资产生产排期和质量门槛 |
| 参考视频用途 | 仅研发内部使用 | 保持参考视频和抽帧不进入候选发布树 |

## 确认后的自动执行顺序

1. 将确认结果写入机器可读产品基线。
2. 重新生成启动器和首发范围映射。
3. 把首发范围从全量双内容包收窄到办公室 10 段/6 槽位，保留城市为后续内容包。
4. 生成 P0 成品资产任务单和权利登记条目。
5. 按 `office-01 → office-06 → office-07 → office-10` 顺序接入模型、动画、灯光和音频。
6. 重新采集首发范围截图，在最终资产和目标设备上逐段人工签收。
7. 配置 Steam Windows 导出和 1080p/手柄 QA；通过后才进入商店准备。

## 当前不自动解除的门禁

即使用户确认本表，以下事项仍必须拿到独立证据，不能由产品确认直接视为通过：

- 最终资产来源与商业许可证。
- 21 段或首发范围内分段的人工视觉签收。
- 目标设备帧率、内存、加载、输入、存档和异常退出验证。
- 隐私政策、客服入口、年龄分级、商店截图、宣传视频和回滚方案。
- `npm run release:preflight` 通过并生成 `release_go`。
