# 动画与音频实现边界

状态：灰盒运行时管线已接入；角色表现状态层已覆盖行走、蹲伏、交互、上下车和受击；最终动画、音效、对白和混音仍未完成。

## 角色动画

当前程序化角色使用游戏逻辑驱动的原地表现：

- 移动速度由角色控制器决定，视觉表现不驱动位移，避免根运动和碰撞状态分裂。
- 行走时使用轻微上下摆动和身体侧倾，蹲伏时降低身体比例和高度。
- 进入载具后隐藏角色表现，退出载具后恢复可见。
- 当前表现只服务于灰盒构图、状态反馈和输入回放，不代表最终角色动画质量。

最终角色资产接入时必须使用统一的原地动画策略，约定如下：

```text
角色_动作_变体
character_idle_default
character_walk_default
character_crouch_default
character_interact_default
character_hit_default
character_fail_default
```

动画必须以第 0 帧静止姿态开始，保持脚底根骨骼一致，不使用未经记录的缩放补丁。移动仍由运行时控制器驱动，动画只负责表现；每个循环必须检查脚底接触、循环首尾和蹲伏过渡。

## 音频事件

音频由 `AudioEventRouter` 统一接收，任务和场景只能发事件，不直接创建播放器。当前已登记的反馈事件包括：交互成功/拒绝、任务成功/失败、感知警报、冲突开始和载具上下车。

当前事件到程序化提示音的映射已移入 `gta-reference-runtime/content/audio_cues.json`；另有 `gta-reference-runtime/content/audio-runtime-catalog.json` 将同一事件绑定到可选最终 `AudioStream`。资源为空或无效时，音频开关打开仍回退到极短的原创程序化提示音，作用是验证事件路由、主音量、类别映射和可访问性备用反馈；默认关闭，不作为参考视频音频或最终音效。暂停菜单已提供音频开关和主音量滑杆。

无头自动化环境没有可用音频设备，因此只保留事件与 `cue_played` 证据，不创建 `AudioStreamGeneratorPlayback`；有音频设备的真实运行时仍执行程序化或最终 `AudioStream` 播放。场景销毁、重启和切换入口时会显式停止并释放动态音频播放器。

最终音频接入前必须补齐：

- 事件到音频资源的映射表。
- 主音量、音乐、效果、对白分组和混音规则。
- 关键状态的字幕或 HUD 备用反馈，不能只依赖声音。
- 音频资源的来源、许可证、循环点和平台压缩设置。
- 办公室潜行、城市冲突、载具驾驶三类真实场景回归。
