# 客服、问题反馈与回滚操作草案

状态：内部发布准备草案；负责人输入清单见 `docs/release-owner-inputs.json`，尚未绑定客服邮箱、Steam 应用编号或正式发行日期。

## 一、当前发布边界

- 产品：《新时代觉醒者》
- 版本形态：首发免费测试版
- 平台：Steam Windows
- 当前工程状态：`internal_no_go`
- 当前不接入真实支付、账号、云存档、广告和在线分析。

## 二、问题反馈入口

正式提交前必须补齐一个可长期维护的公开入口，并在游戏开始页、暂停菜单或商店页面保持一致。字段不得由工程自动猜测，具体待确认项统一登记在 `docs/release-owner-inputs.json`：

```text
客服邮箱：待确认
反馈表单或工单地址：待确认
隐私政策地址：待确认
支持语言：简体中文（其他语言待确认）
```

内部测试期间，问题报告至少应包含：构建版本、Windows 版本、分辨率、输入设备、复现步骤、是否能读取检查点、日志和截图。不得要求用户上传参考视频或含个人信息的文件。

## 三、问题分级

| 等级 | 示例 | 处理要求 |
|---|---|---|
| 阻断 | 无法启动、存档损坏、任务无法完成、严重崩溃 | 暂停该构建公开测试，复现并建立修复候选 |
| 严重 | 键鼠/手柄不可用、关键视觉或音频缺失、持续卡死 | 进入下一构建前必须复测 |
| 一般 | 文案、布局、非关键表现问题 | 登记版本、场景和修复优先级 |

## 四、回滚策略

1. 每次候选构建保留 Windows 文件、源码指纹、构建哈希、导出模板哈希和发布清单。
2. 新构建通过 `npm run release:preflight` 前，不得替换已验证的公开构建。
3. 若公开构建出现阻断问题，停止发布推广，保留当前构建证据，恢复到最近一个通过目标设备 QA 的构建。
4. 回滚后重新验证启动、任务完成/失败、存档读取、音频设置、输入设备和崩溃恢复；不能只替换可执行文件而跳过证据绑定。
5. Steam 上传、分支、公告和商店截图必须绑定同一个构建身份；当前尚未获得 Steam 应用编号，因此不生成真实上传配置。

## 五、当前不能宣称的内容

本草案不能替代 Windows 10/11 真机 QA、最终资产权利签收、视觉逐帧验收、隐私政策、客服入口或 Steam 提交审核。当前发布前置仍必须保持阻断。
