# 平台与输入验收矩阵

状态：平台无关基线；不是任何平台的最终兼容声明。

## 0. 最快可玩路径

内部试玩不等于正式首发平台。当前最快路径是使用桌面开发机运行：

```text
npm run playtest:desktop
```

这条路径只用于尽快验证办公室任务、镜头、NPC、失败重试、城市任务和存档回放；它不要求现在决定 Android、iOS 还是 Steam，也不代表已经完成目标设备 QA。

正式平台决策可以在桌面内部试玩和第一轮用户反馈之后再定：

1. 先用桌面开发包完成可玩性和行为回放。
2. 根据反馈选择 Android 首发、Steam Windows 首发，或两阶段发布。
3. 冻结目标设备后再接入触屏、安全区域、平台输入、导出和商店门禁。

运行时使用动作意图而不是把平台按键写进任务规则。当前动作清单见 `gta-reference-runtime/scripts/input_actions.gd`；目标平台确认后，只扩展输入映射和界面提示，不修改任务状态机。

## 2. 已有证据与未验证项

已验证：

- 游戏规则读取命名动作，不直接依赖平台设备事件。
- 键盘动作和手柄动作已注册并通过自动化映射检查。
- 暂停已进入统一动作层，键盘 Esc 与手柄开始键均已注册并通过场景事件测试。
- 输入帧可以被记录、回放和用于确定性测试。
- 输入帧进入场景规则前会统一处理非有限值和单帧幅度；非法回放会被拒绝，不会静默放大镜头或移动结果。
- 暂停菜单不会继续推进任务模拟，读取存档和重试有独立动作。

未验证：

- 真实手柄设备、摇杆死区、不同手柄布局和断连重连。
- 鼠标灵敏度、窗口失焦、锁屏和高分辨率窗口缩放。
- 触屏虚拟摇杆、触摸交互、系统返回键和安全区域。
- 目标平台菜单键、文本输入、系统暂停和后台恢复。

## 3. 平台选择影响

| 平台方向 | 必增工作 | 主要风险 | 需要的验收设备 |
|---|---|---|---|
| 桌面端 | 鼠标捕获、窗口缩放、键位提示、手柄兼容 | 多分辨率、输入焦点、显卡差异 | 至少一台目标系统设备和一只手柄 |
| 移动端 | 虚拟摇杆、触摸交互、分辨率安全区、性能降级 | 触控误操作、热量、内存和机型碎片化 | 低/中/高三档真实设备 |
| 主机或客厅设备 | 菜单焦点、手柄布局、暂停/恢复、认证规则 | 平台认证、存档和系统生命周期 | 每个目标平台的开发机/测试机 |
| 桌面端 + 移动端 | 同时完成以上两组 | 交互模型和性能目标冲突 | 两套完整设备矩阵 |

## 5. 进入平台适配的条件

只有在用户确认首发平台和设备范围后，才允许：

1. 增加平台专用输入映射和触屏/菜单实现。
2. 创建平台导出配置和正式构建身份。
3. 修改 HUD 尺寸、字体和安全区域以适配目标设备。
4. 用目标设备实测性能、存档、异常恢复和输入。
5. 把对应平台的证据写入发布候选清单。

未确认前，当前运行时继续保持平台无关灰盒状态。
