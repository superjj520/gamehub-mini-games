# 视觉方向定稿门禁

版本：`0.1.0-dev`  
状态：`已确认，进入 P0 候选生产与逐项视觉验收`

本文件把两个参考视频转化为可以交给建模、动画、灯光和程序执行的选择。它不改变当前运行时，也不把灰盒截图标记为视觉通过。

## 当前参考画面的可观察事实

- 视角是第三人称肩后镜头，角色占画面中下部，环境和 NPC 密度是任务压力的一部分。
- 城市场景需要真实街边店铺、卷帘门、中文招牌、密集人群、道路和三轮车。
- 办公室场景需要真实工位、隔断、电脑、灯光、角色服装、蹲伏和巡查动作。
- 失败、警觉、冲突、交互和驾驶都依赖角色动作、遮挡、材质和灯光共同表达。
- 当前运行时已经具备上述空间和行为骨架，但角色、环境、动画和材质仍是灰盒。

## 选项一：原创写实，中等细节（推荐）

白话：看起来像真实拍摄的三维游戏画面，但不复制参考视频中的具体模型、人物、商标或地图。

执行标准：

- 人物使用完整人体比例、服装分层、头发、背包和手部动作。
- 建筑、工位、门面、货架和三轮车使用 PBR 材质、真实边缘和可读细节。
- 使用统一暖色灯光、环境遮蔽、软阴影和有限后处理。
- 角色与镜头比例优先贴近参考帧，再按目标设备做 LOD 和纹理压缩。
- 这是唯一适合“尽量接近参考视频画面”的路线。

代价：资产制作和动画工作量最高；在最终签收前，必须逐段重采集截图并人工确认。

## 选项二：原创低多边形写实

白话：保留第三人称、城市、任务和人群，但人物和环境明显简化，使用更少的面数、更简单的材质和更夸张的轮廓。

执行标准：

- 角色以简化几何体和少量材质表现。
- 环境保留构图、颜色和交互位置，但不追求真实表面细节。
- 优先帧率、加载速度和单人快速制作。

代价：最快可玩，但无法满足参考视频的逐帧视觉还原；只能作为“同一玩法框架”的版本，不能作为 100% 视觉还原版本。

## 本项目已确认选择

由于“100%还原度”是硬标准，本项目已确认：

```text
最终视觉方向：原创写实，中等细节，保留移动端优化能力
```

“保留移动端优化能力”只表示资产从一开始控制面数、纹理和材质预算，不代表现在就决定首发手机端。

## 确认后执行的工作

按以下顺序进入候选生产、人工审阅和最终资产替换：

1. 玩家角色、上司和巡查 NPC 的完整模型与动作。
2. 办公室工位、隔断、走廊、电梯厅和灯光。
3. 城市店铺、人群、道路、三轮车和交互道具。
4. 统一材质库、LOD、碰撞和运行时挂载。
5. 重新采集优先分段 `office-01`、`office-06`、`city-01`、`city-04`。
6. 通过人工视觉签收后，再扩展到其余分段和平台构建。

当前确认只解除视觉方向决策，不解除最终资产权利、人工逐帧验收、Windows 目标设备、商店材料或发布门禁；任何程序化灰盒资产仍不得宣称为成品。
