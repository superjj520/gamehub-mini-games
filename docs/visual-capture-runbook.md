解锁后也可以使用安全收口入口，先预检采集输出目录；确认 21 张 PNG 已人工抽查后再追加 `--write`。该入口会核对当前源码指纹、原创边界目录、PNG 数量和事件清单，失败时恢复正式证据，不会自动通过视觉：

```text
npm run finalize:reference:capture -- --source-dir /tmp/new-era-formal-capture --method visible_window --operator "验收人" --captured-at "2026-10-15T00:00:00.000Z"
npm run finalize:reference:capture -- --source-dir /tmp/new-era-formal-capture --method visible_window --operator "验收人" --captured-at "2026-10-15T00:00:00.000Z" --write
```

正式同步脚本现在还会强制核对 `matrix-manifest-editor.json`、每个矩阵条目和事件清单中的源指纹与文件数。当前源不一致、字段缺失或条目不完整时，脚本会在写入前失败；这类失败是保护证据链，不是视觉采集成功。

当前对照报告由 `scripts/compare_visual_evidence.sh` 生成，报告只能保持 `unverified`；它不能代替人工签收，也不能因为像素误差低就自动通过。

扩展视觉采集完成后，若运行时源指纹因本轮研发发生变化，必须确认 PNG 是刚刚由真实窗口生成的，再执行 `npm run sync:visual-expansion:current`；普通 `npm run sync:visual-expansion` 会拒绝旧指纹，防止误绑陈旧截图。

`npm run verify:visual-matrix` 只验证已经保存的图形证据，不会启动 Godot 窗口；因此它不能替代本节第一步的真实图形采集。

## 3. 对照记录要求

每个分段必须同时保存：

- 参考帧路径和来源视频时间段。
- 当前运行时截图、PNG 哈希和源码指纹。
- 行为事件、输入回放和状态快照。
- 人工差异清单：角色比例、镜头距离/高度、构图、HUD、颜色、光照、关键道具、动画和音频节奏。
- 验收人、验收时间、结论和返工项。

## 4. 失败处理

- 图形窗口服务不可用：保留旧矩阵，记录采集失败，不把旧截图绑定到新源码。
- 只有无头渲染：只执行行为和数据验证，视觉保持 `unverified`。
- 参考视频分辨率或音频不足：保持证据边界，不猜测缺失内容。
- 运行时源码变化：废弃受影响候选截图，重新采集并重新生成对照报告。
- 最终资产替换灰盒：重新执行全部受影响分段的行为、视觉、权利和目标设备验收。
