# 产品基线确认包

版本：`0.1.0-dev`

状态：`已确认；作为历史决策说明保留`

用途：把当前已验证的运行时能力、两个参考视频的范围、首发取舍和发布阻断项集中为一份决策说明。机器可读决定仍以 `docs/product-baseline-decision.json` 为准。

## 1. 产品定义

我们要制作一款原创的第三人称任务游戏：玩家在现实生活质感的三维场景中观察环境、选择路线、处理 NPC 反应、完成短任务，并在成功、失败和重试之间形成可重复的游戏体验。

“GTA 类型底层”只表示第三人称角色、城市空间、载具、NPC、交互、任务、HUD、存档和开放街区运行时能力；产品不得复制任何既有游戏的名称、角色、地图、模型、纹理、音频、代码、商标或可识别表达。

两个本地参考视频只作为内部行为、镜头节奏和视觉验收输入。参考视频、抽帧和未经授权的内容不得进入发布包或商店素材。

## 2. 目标玩家与核心体验

### 目标玩家

- 喜欢 5–20 分钟短任务和强反馈的玩家。
- 喜欢潜行、路线选择、NPC 感知和突发失败的玩家。
- 喜欢第三人称街区探索、轻载具和连续目标的玩家。

### 核心体验承诺

玩家在 30 秒内理解当前目标和失败风险；移动、蹲伏、交互、载具和任务状态都由真实运行时驱动；失败原因可理解，重试可以复现；最终画面、镜头、动作、HUD、音频和关键状态必须逐段对照参考证据。

## 3. 推荐首发方案

以下方案已经由用户确认并写入机器可读决策文件。

| 项目 | 推荐值 | 原因 |
|---|---|---|
| 内部测试平台 | Windows 桌面源码试玩包 | 当前桌面运行时已经可启动和回放，最快验证任务闭环 |
| 正式发布平台 | Steam Windows | 延用现有键鼠/手柄基础；仍需目标设备、导出模板和商店门禁 |
| 首发范围 | 办公室《准点下班》垂直切片 | 先把感知、潜行、镜头、失败重试和视觉还原做到可签收 |
| 第二内容包 | 城市《街区扫码任务》 | 继续保留为扩展内容，不与首发视觉资产生产并行抢资源 |
| 视觉方向 | 原创写实，中等细节资产 | 参考画面是写实三维场景；低多边形会明显降低逐帧相似度 |
| 内容政策 | 全部原创资产；参考视频只用于内部验收 | 保护商业发布边界，避免把参考素材误当成可发布资产 |
| 首发时长 | 5–10 分钟办公室任务 | 与当前垂直切片能力和单一平台 QA 范围匹配 |
| 商业化 | 首发先不接真实支付和复杂经济系统 | 降低隐私、支付、账号和商店合规复杂度，待核心体验验证后决定 |

## 5. 首发成功标准

以下是定稿后必须同时满足的条件：

1. 产品基线、平台、版权边界、视觉方向和预算已确认并写入机器可读决策文件。
2. 首发范围内的每个参考分段都有真实输入、事件时间轴、运行时截图和逐段视觉签收。
3. 首发范围内的最终角色、环境、NPC、动画、载具、道具和音频全部为原创或有明确商业许可。
4. 任务、NPC 感知、交互、失败、重试、存档和异常恢复在固定构建上可重复。
5. 目标设备完成输入、分辨率、性能、内存、加载、存档和异常退出验证。
6. 隐私、客服、年龄分级、商店图文、版本回滚和热修复材料齐全。
7. `npm run release:preflight` 退出码为 0，发布报告状态从 `internal_no_go` 变为 `release_go`。

### 已验证

- Godot 运行时的第三人称角色、镜头、NPC 感知、任务状态机、城市、交互、载具、HUD、存档和异常恢复灰盒闭环。
- 21/21 分段的结构化行为事件证据和输入计数。
- 21 个分段的运行时截图登记与源指纹绑定链路已经建立；当前源有效 PNG 为 `0/21`，历史截图不得重新绑定，差异报告链路不等于视觉完成。
- 两个本地参考视频的源 SHA-256、文件大小、视频/音频流元数据、21 个分段时间边界和抽帧哈希均可由 `node scripts/verify_reference_media.mjs` 复核；这些媒体仍仅限内部验收。
- 自动化测试、内容包校验、资产目录校验、进程级异常退出恢复和当前主机性能烟雾测试。

### 未验证或未完成

- 21/21 视觉分段目前均为 `unverified`，不代表 100% 视觉还原。
- 最终角色、动画、环境、NPC、载具、道具、音频和灯光资产尚未生产。
- Windows 目标设备、手柄实机、内存、加载、断电恢复和 Steam 发布链尚未验证；触屏不属于当前首发范围。
- 参考视频不进入游戏或商店；最终资产的原创来源、生成工具和商业许可仍需逐项登记。
- 隐私政策、商店材料、商业化、回滚和热修复流程尚未完成。

## 7. 两个视觉方向的白话解释

### 原创写实

角色、家具、街道、材质、灯光和动画都尽量接近真实世界。它更适合当前参考视频，也更有机会通过逐帧视觉验收，但建模、动画、灯光、优化和设备测试成本更高。

### 原创低多边形写实

仍然是原创三维游戏，但用更少的面、更简单的材质和更夸张的轮廓来表现。它适合快速做出可玩的版本，但与参考视频的真实角色、环境细节和光照会产生明显差异，不适合作为“尽量一模一样”的最终方向。

基于你要求的视觉还原度，本项目建议选择“原创写实（中等细节、移动端可优化）”，而不是低多边形方向。


机器可读的 `launch_scope` 只能填写一个值：`office_vertical_slice` 或 `office_and_city`。`npm run verify:release-scope` 会验证这两个范围与实际分段、资产槽位的映射；发布预检会按确认值只检查首发范围内的资产和视觉分段，但不会降低范围内的逐项验收要求。

你已说明两个视频由你制作；当前产品基线将它们登记为“用户提供的研发参考素材”，可用于本地保存、抽帧、对照、剪辑增强和内部优化，但视频本体、抽帧图和未经单独审核的衍生媒体不得进入发布包、商店页面或宣传片。若未来要公开使用视频本体或衍生媒体，必须另外确认发布用途、生成工具和输入素材的商业许可边界，不能由本文件的研发授权自动推导。

当前可以进入 P0 原创资产生产和 Steam Windows 导出准备，但在最终资产、目标设备和视觉签收完成前，不生成可上架结论、不提交商店。

为避免手工编辑造成范围或权利字段缺失，可先把完整候选决策保存为独立 JSON，再执行 `npm run product:record -- --source <候选 JSON>` 预览。只有确认无误后，才允许显式追加 `--write` 写入机器可读基线；该工具不会自动替你选择任何字段。

## 9. 定稿后的执行顺序

1. 已把确认结果写入 `docs/product-baseline-decision.json`。
2. 已冻结首发范围、平台设备和视觉方向，并建立可复现内部候选树。
3. 按资产生产清单制作原创资源，逐槽位接入运行时契约。
4. 重新采集首发范围的固定构图、事件轨迹和视觉对照，并逐段签收。
5. 生成目标平台构建，完成真机 QA、隐私和商店材料。
6. 清零阻断项后再执行 `npm run release:preflight`，由产品、工程、QA、权利和发布负责人共同签署 Go/No-Go。
