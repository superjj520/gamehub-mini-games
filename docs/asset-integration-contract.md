# 最终资产接入契约

状态：灰盒到最终资产的接入规范；最终资产尚未开始生产。

目的：替换程序化灰盒时，只替换表现层，不改变已经验证的碰撞、任务、交互、存档和参考验收锚点。

## 1. 通用不可变接口

每个可交互或可移动资产必须保留一个运行时根节点。根节点负责位置、碰撞、状态和存档引用；视觉模型、材质、动画和音频挂在根节点下。角色表现资产若提供 `AnimationPlayer` 或 `AnimationTree`，运行时会按统一状态名驱动动画；缺少某个动画时仍保留灰盒或静态视觉回退。

```text
资产根节点
├── 碰撞体                 # 由运行时或经过验收的资产碰撞提供
├── Visual                  # 可替换模型、材质和灯光挂点
├── AnimationPlayer/Tree    # 可替换动画表现，不拥有任务状态
├── SFX                     # 只发出已登记的音频事件
└── Anchors                 # 交互、镜头、握持、脚底和特效挂点
```

禁止在最终资产中直接写任务阶段、库存、奖励、NPC警觉或存档字段；这些状态只能由对应运行时系统拥有。

## 2. 资产类别契约

| 类别 | 必须保留的锚点/接口 | 替换验收 | 不能改变的行为 |
|---|---|---|---|
| 主角 | 脚底原点、胸口镜头锚点、左右手握持点、交互动作入口 | 站立/蹲伏高度、碰撞半径、镜头遮挡、动画时长；动画名为 `idle_default`、`walk_default`、`crouch_default`、`interact_default`、`vehicle_default`、`hit_default`、`fail_default` | 移动、蹲伏、交互、上下车、存档位置 |
| 办公室 NPC | 脚底原点、视线起点、搜索目标点、警觉标记点 | 视野射线、遮挡、问号/感叹号位置、巡逻路径 | 感知状态、失败条件、搜索状态 |
| 城市行人 | 脚底原点、碰撞体、路线挂点、被推开恢复点 | 人群密度、碰撞和冲突位移 | 冲突状态和重试恢复 |
| 载具 | 车体原点、驾驶座、上下车点、车轮接触点、碰撞体 | 上下车距离、驾驶者绑定、转向和摄像机跟随 | 载具状态、驾驶者、存档字段 |
| 环境模块 | 底面/拼接原点、导航边界、碰撞层、交互挂点 | 走行区域、遮挡、镜头碰撞、门/货架/电梯距离 | 任务目标 id、交互条件和导航事件 |
| 交互道具 | 交互中心、提示锚点、碰撞体、一次性状态接口 | 距离、提示、成功/阻断反馈 | 交互条件、库存和任务阶段 |
| HUD | 任务、时间、警觉、提示、地图和结果区域 | 文字层级、分辨率、安全区、输入提示 | 任务状态、奖励和存档状态 |
| 音频 | 事件 id、类别、优先级、时长和混音总线 | 事件时机、音量、重复策略和关闭设置 | 任务规则和失败条件 |

## 3. 接入顺序

1. 权利负责人登记来源、许可、作者和可发布范围。
2. 技术美术通过单位、轴向、原点、骨骼、材质、碰撞和面数检查。
3. 程序接入运行时根节点，保留旧接口和节点名称。
4. 逐个运行正常流程、失败流程、重试和存档恢复。
5. 重新采集受影响参考分段的截图和输入回放。
6. 通过目标设备性能、内存、加载和输入测试后，才能把资产状态改为可发布。

当前运行时已经提供 `scripts/asset_runtime_catalog.gd` 和 `content/asset-runtime-catalog.json` 作为可选表现层入口，并提供 `content/audio-runtime-catalog.json` 作为音频事件到最终 `AudioStream` 的替换目录。表现层 `scene_path` 为空或资源未能实例化时，运行时挂载现有程序化灰盒回退；音频 `stream_path` 为空或资源无效时，运行时回退到程序化提示音。正式资源路径必须先通过目录校验，再经过权利、接口、行为、视觉和目标设备验收后才能进入发布候选。

资产生产清单进入 `release_candidate` 前，还必须通过 `npm run verify:asset-delivery`。该门禁把三种状态分开处理：未定稿但已接入的槽位可以挂载明确命名为 `candidate` 的候选场景，但必须保持 `candidate_integrated_unverified`、`release_allowed=false` 和 `procedural_graybox` 回退；未接入槽位必须保持空资源路径；一旦槽位声明为成品，就必须同时提供存在的 `asset_package`、可复核的 `delivery_evidence`、同 id 的可发布权利记录、已签收的平台字段，以及 `scene_path`/`stream_path` 和 `forbid` 回退策略。这样“候选视觉被误报为成品”或“正式资源路径写错后悄悄继续显示灰盒”都会被发布前门禁阻断。

## 5. 当前工程约束

- 当前 8 个资产槽位全部是灰盒，不能标记为最终资产。
- 当前 8 个槽位均通过“显式灰盒回退”分支；这不是最终资产交付通过，也不提升视觉验收状态。
- 参考视频和抽帧只用于内部验收，不能作为纹理、材质、宣传截图或音频素材。
- 未确认平台前，性能预算只作为草案；不能以当前主机读数替代目标设备签收。
- 任何资产替换都必须重新绑定源指纹、截图哈希和受影响的验收分段。
