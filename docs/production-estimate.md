# 研发投入估算与确认表

状态：提案，不是预算承诺；产品、首发平台、首发范围、原创版权边界和视觉方向已确认，预算与最终资产采购仍未定稿。

本表使用“单人全职等效周”估算，表达相对工作量，不等同于日历工期。多人并行可以缩短日历时间，但会增加协作、验收和资产管理成本。

当前已经完成：Godot 灰盒运行时、办公室与城市行为闭环、参考证据库、21 段行为矩阵、截图对照链路、存档/异常恢复测试和发布门禁框架。

这些成果不能抵扣最终资产、目标设备、平台合规和视觉签收工作，只能降低后续运行时重写风险。

## 3. 三种范围方案

| 方案 | 首发范围 | 预计总投入 | 适用条件 | 当前状态 |
|---|---|---:|---|---|
| A：办公室垂直切片 | 一个场景、一个平台、短流程 | 20–35 人周 | 先验证核心体验和视觉方向 | 当前已确认首发基线：Steam Windows |
| B：办公室 + 城市 | 两个场景、一个平台、完整任务链 | 36–60 人周 | 有稳定美术/动画/音频投入 | 后续扩展，不纳入当前首发基线 |
| C：双平台首发 | 办公室 + 城市、两个平台 | 44–76 人周 | 同时具备目标设备、发布和 QA 能力 | 后续扩展，不纳入当前首发基线 |

以上范围不包含购买资产、外包单价、设备、商店账号、法务、税费和市场投放费用。若最终使用高写实角色、复杂动画或原始高分辨率参考，资产和视觉验收工作量应向上调整。

## 4. 成本计算方式

```text
研发预算 = 人周 × 团队综合人周成本
         + 最终资产/外包费用
         + 目标设备和测试费用
         + 平台账号、法务、商店与本地化费用
         + 预留风险金（建议按未定项另行核算）
```

不在用户确认前填写具体货币金额，避免把平台、团队构成和美术方向的假设伪装成正式报价。
