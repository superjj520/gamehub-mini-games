# GTA 类型参考游戏还原与产品化执行标准

> 状态更新：2026-10-05。本文最初记录的是工程建立前的审计基线；当前可运行工程位于 `gta-reference-runtime/`，已有角色、镜头、NPC 感知、任务、城市、交互、载具、HUD、存档和自动化验证。最终资产和上架门禁仍未完成。

## 1. 项目决策

本项目不以“做一个看起来像的演示”为完成标准，而以参考视频中的可观察结果为验收标准。

目标分为两层：

1. **参考还原层**：角色、镜头、任务、NPC、交互、HUD、失败重试、节奏和反馈必须逐项可复现。
2. **通用运行时层**：把参考视频中的行为抽象成可配置的 GTA 类型游戏底层，支持后续城市、任务、NPC、载具和角色扩展。

“100%还原”在产品上定义为：所有已取得证据覆盖的行为和画面要素，都必须有实现记录、自动化测试或逐帧对比证据；没有证据的部分必须标记为待确认，不能用猜测补齐。

## 2. 当前证据边界

当前已有两个本地视频：

- `video-1-china-gta-480.mp4`：城市任务、免费鸡蛋、NPC人群、交互、载具和街道任务。
- `video-2-off-work-480.mp4`：办公室潜行、时间目标、NPC感知、警觉、失败和重试。

这两个文件可以支撑玩法逻辑、镜头节奏和状态机分析，但由于是 `480×270` 版本，不能单独证明像素级视觉还原。正式视觉验收还需要原始分辨率、完整音频和更完整的操作证据。

## 3. 推荐底座

首选 Godot 4.x，锁定具体稳定版本后再开始正式开发。Godot 的角色、导航、动画、场景和跨平台能力足以支撑首个垂直切片；载具部分先做可替换接口，不把默认载具物理直接视为最终方案。

候选能力只允许按以下顺序使用：

1. Godot 官方 TPS Demo：角色、镜头、动画和输入基线。
2. Godot 官方导航与动画系统：NPC寻路、状态切换和动画混合。
3. `City Action Prototype`：参考任务、车辆、交通、警察和测试系统的拆分方式。
4. `GTA-mini`：参考城市任务、热度、行人和载具之间的组合方式。
5. Chickensoft GameDemo：参考状态机、存档和自动化测试组织方式。

第三方项目不得直接复制美术、声音、角色、地图、品牌、车辆造型或受限制代码。每个候选仓库都必须先锁定提交版本、记录许可证、记录资产来源，并形成依赖清单。

## 4. 运行时模块

```text
runtime/
├── player/              玩家移动、动作、受击、交互
├── camera/              第三人称跟随、瞄准、遮挡和镜头状态
├── npc/                 行人、敌对角色、老板、警察和群体行为
├── perception/          视野、听觉、警觉、最后目击点
├── navigation/          路网、导航网格、动态避让和区域切换
├── interaction/         物品、门、电梯、柜台、载具和任务对象
├── vehicle/             上下车、驾驶、碰撞、载具状态和交通
├── mission/             目标、条件、奖励、失败、重试和阶段切换
├── world/               城市区域、室内外连接、流式加载
├── hud/                 时间、地图、目标、生命、金钱、警觉提示
├── save/                任务进度、角色状态和版本迁移
└── reference_qa/        回放、截图、时间轴和逐帧验收
```

## 5. 第一轮基准测试

第一轮不是做完整游戏，而是做两个可以反复回放的基准场景。

### 基准场景 A：准点下班

验证：

- 角色行走、蹲伏和镜头跟随。
- NPC视野、警觉问号、红色发现状态。
- 时间从 `17:59` 到目标时间的推进。
- 电梯、门、走廊等交互对象。
- 失败、重试和任务完成状态。
- HUD目标文字和警觉反馈的时间点。

### 基准场景 B：免费鸡蛋

验证：

- 城市第三人称移动和人群碰撞。
- 物品领取、携带和任务目标变化。
- NPC冲突和简单追踪。
- 载具上下车与街道移动。
- 地图、金钱、生命、任务目标和店铺目标。

## 6. 完成定义

一个功能只有同时满足以下条件，才允许标记为完成：

1. 有参考视频时间点或明确设计证据。
2. 有实现模块和配置入口。
3. 有正常流程测试。
4. 有失败、重试和边界测试。
5. 有录屏或截图与参考画面对比。
6. 在目标设备上完成性能和输入验证。

以下问题任意一个存在，都不能进入发布候选版本：

- 镜头位置或跟随节奏明显不同。
- NPC发现时机不同。
- 任务目标切换不同。
- 失败条件或重试流程不同。
- HUD状态、颜色、数值或动画不同。
- 交互对象只有视觉占位，没有真实状态变化。
- 载具只可展示，不能完成完整上下车和驾驶流程。

## 7. 当前工作区结论

当前工作区已经具备可运行的 Godot 灰盒工程、独立内容目录和本地 Git 版本库，`gta-reference-runtime/` 是当前研发入口；它不是最终上架工程，因为尚未建立平台导出流水线、最终资产包和商店材料。早期“只有设计草稿和轮盘图片”的结论仅适用于工程建立前，不再作为当前状态依据。

在进入最终资产和上架阶段前，仍需完成：

1. 用户确认首发平台、品牌、预算和参考素材商业授权。
2. 在本地 Git 仓库中建立首个基线提交，并完成平台导出流水线。
3. 为最终角色、动画、材质、音频和城市资产完成权利登记。
4. 解决真实窗口/目标设备的逐帧视觉、输入、性能和存档回归。
5. 两个基准场景的逐帧对比全部通过，并完成商店、隐私和回滚材料。

只有基准场景通过，才进入城市扩展、更多角色、载具交通和商业化内容生产。
