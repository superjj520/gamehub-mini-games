# P0 成品资产生产规格包

版本：`0.1.0-dev`  
状态：产品基线已确认，进入 P0 生产规格执行阶段；不代表资产已经完成或可发布。  
适用范围：办公室垂直切片优先，同时保留城市任务的接口兼容性。

## 1. 使用规则

本规格包只定义“做什么、做到什么程度、如何接入和如何验收”，不替用户决定最终美术风格。默认按“原创写实、中等细节”估算；如果最终选择其他方向，只允许替换材质、面数和表现层，不得破坏运行时契约、碰撞、挂点、动画名称和证据路径。

所有资产进入运行时前必须完成：

1. 来源、生成工具、许可证和商业使用范围登记。
2. 单位、朝向、原点、碰撞体和挂点检查。
3. 办公室与城市至少各一次真实运行时接入。
4. 行为回放、固定镜头截图和目标设备性能证据。
5. 人工视觉签收；未签收保持 `unverified`。

## 2. P0-01 玩家角色

| 项目 | 规格 |
|---|---|
| 运行时身份 | `player-character` |
| 视觉目标 | 可辨识的原创成年主角，服装、背包、发型和手部轮廓在肩后镜头中稳定可读 |
| 几何预算 | 单体最多 35,000 三角面；移动端候选 LOD 不超过 12,000 三角面 |
| 材质预算 | 4 个以内材质槽；主贴图 2048，LOD 贴图 1024 |
| 必备动画 | `idle_default`、`walk_default`、`crouch_default`、`interact_default`、`vehicle_default`、`hit_default`、`fail_default` |
| 必备挂点 | 脚底原点、胸口镜头锚点、左右手握持点、背包挂点、载具驾驶点 |
| 首批镜头 | `office-01`、`office-02`、`city-01`、`city-06` |
| 建模参考板 | [原创玩家角色四视图参考板](../art-source/characters/player-design/new-era-awakener-player-turnaround-v1-generated.png)；只作为建模输入，不是最终运行时资产 |
| 失败条件 | 脚底漂移、手持物穿模、蹲伏高度错误、上车后角色消失、失败动画不触发 |

## 3. P0-02 办公室 NPC

| 项目 | 规格 |
|---|---|
| 运行时身份 | `office-npc-set` |
| 视觉目标 | 上司与巡查 NPC 具备服装、发型、体型和警觉状态差异；远景仍能读出朝向 |
| 几何预算 | 单体最多 18,000 三角面；远景 LOD 不超过 6,000 三角面 |
| 材质预算 | 3 个以内材质槽；主贴图 1024 |
| 必备动画 | `idle_default`、`walk_default`、`search_default`、`alert_default` |
| 必备挂点 | 脚底原点、视线起点、搜索目标点、警觉标记点 |
| 首批镜头 | `office-04`、`office-06`、`office-07`、`office-08` |
| 建模参考板 | [原创办公室 NPC 四视图参考板](../art-source/characters/office-npc-design/new-era-awakener-office-npc-turnaround-v1-generated.png)；只作为建模输入，不是最终运行时资产 |
| 失败条件 | 视线起点因模型替换改变、搜索状态无动作、警觉方向与逻辑不一致、碰撞体偏移 |

## 4. P0-03 办公室环境

| 项目 | 规格 |
|---|---|
| 运行时身份 | `office-environment-kit` |
| 视觉目标 | 工位、隔断、电脑、文件、走廊、电梯厅和暖色灯光形成连续空间；掩体关系必须与灰盒一致 |
| 模块化要求 | 工位、隔断、门、墙、灯具、电梯门厅可独立替换；不在场景脚本内写单件缩放补丁 |
| 几何预算 | 单建筑/模块最多 12,000 三角面；重复工位优先实例化 |
| 材质预算 | 建筑模块最多 3 个材质槽；小道具共用材质图集 |
| 必备交互 | 工位掩体、门口遮挡、电梯按钮、检查点恢复位置 |
| 首批镜头 | `office-01`、`office-03`、`office-05`、`office-06` |
| 失败条件 | 墙体遮挡镜头、导航边界变化、门框穿透、检查点读取后空间状态不一致 |

## 5. P0-04 城市店铺与街区

| 项目 | 规格 |
|---|---|
| 运行时身份 | `city-environment-kit` |
| 视觉目标 | 店铺门头、卷帘门、货架通道、道路、路缘、街灯和后场仓储具备可读地标与连续遮挡 |
| 模块化要求 | 店铺立面、道路段、路缘、街灯、仓储门头、装卸点可拼接；入口坐标继续由内容包提供 |
| 几何预算 | 单建筑模块最多 12,000 三角面；道路和路缘必须支持实例化 |
| 材质预算 | 建筑、道路、金属、玻璃、湿润路面分层；雨后配置不得复制整套场景 |
| 必备状态 | 白天、黄昏、雨后；街道→店内→出口→后场仓储连续切换 |
| 首批镜头 | `city-01`、`city-03`、`city-05`、`city-08`、`city-11`、扩展街区截图 |
| 失败条件 | 招牌不可读、店内外曝光断裂、入口/装卸点不可辨识、天气切换破坏碰撞或帧率 |

## 6. P0-05 三轮车

| 项目 | 规格 |
|---|---|
| 运行时身份 | `three-wheel-vehicle` |
| 视觉目标 | 车体、车轮、驾驶位、货架、座椅、车把和载货物可读；驾驶者上车后保持正确姿态 |
| 几何预算 | 车体最多 25,000 三角面；损伤表现优先使用材质状态而非复制车体 |
| 材质预算 | 车体、金属、轮胎、货物和损伤状态分层；贴图主规格 2048 |
| 必备状态 | 空车、载货、驾驶、碰撞轻伤、耐久不足、失败停机 |
| 必备挂点 | 车体原点、驾驶座、上下车点、车轮接触点、碰撞体、货架挂点 |
| 首批镜头 | `city-06`、`city-07`、`city-08`、`city-09`、载具损伤扩展截图 |
| 失败条件 | 车轮悬空、角色座椅偏移、碰撞后速度异常、耐久 HUD 与实际值不一致、存档后驾驶状态丢失 |

## 7. P0 联合验收顺序

1. 先接入玩家角色和办公室环境，完成 `office-01`、`office-06`。
2. 接入 NPC，完成 `office-04`、`office-07` 的感知/失败回放。
3. 接入城市店铺和三轮车，完成 `city-01`、`city-06`、`city-08`。
4. 接入后场仓储与天气配置，完成扩展视觉矩阵对应截图。
5. 在同一构建身份下重采集行为轨迹、21 段参考截图和 18 项扩展截图。
6. 先由程序验证碰撞、导航、输入、存档和性能，再由人工进行逐段视觉签收。

## 8. P0 通过条件

P0 不能因为“模型已经放进场景”而通过，必须同时满足：

- 权利记录完整且允许商业发布。
- 运行时替换不改变行为回放结果。
- 办公室和城市固定镜头均有真实截图。
- 参考分段和扩展状态均完成视觉人工签收。
- 目标平台设备完成分辨率、帧率、内存、加载和输入验证。
- `npm run verify:evidence-binding`、`npm run verify:asset-delivery`、`npm run release:preflight` 均通过。

在以上条件满足前，P0 状态只能是 `candidate` 或 `unverified`，不能写成 `release_ready`。
