# 视觉修复与最终资产生产计划

版本：`0.1.0-dev`  
状态：产品基线已确认；本计划是 P0 资产生产与验收执行单，不构成商店发布授权。

## 1. 执行原则

1. 只使用原创或已取得商业许可的资产；参考视频、抽帧和差异报告只作为内部验收证据。
2. 先完成会影响多个分段的共享资产，再处理单个镜头的局部调整。
3. 每个资产必须通过运行时挂载契约、行为回放、目标平台截图和权利登记，才能进入视觉签收。
4. 任一分段的角色、环境、镜头、HUD、动画或音频仍有明确差异时，保持 `unverified`，不允许用平均像素指标替代人工判断。

## 3. 分段处理顺序

### 第一批：构图基准

优先处理 `office-01`、`office-06`、`city-01`、`city-04`。

这四段分别覆盖办公室出生镜头、电梯厅冲突、城市店铺人群和冲突道具。它们通过后，才能确认共享角色比例、镜头距离、环境尺度和 HUD 层级没有根本错误。

### 第二批：状态连续性

处理 `office-02` 至 `office-05`、`city-02` 至 `city-07`，重点验证遮挡、感知、交互、库存和登记反馈在最终资产替换后仍与灰盒回放一致。

### 第三批：移动与收尾

处理 `office-07` 至 `office-10`、`city-08` 至 `city-11`，重点验证失败/重试、连续驾驶、目标门面和最终任务收束镜头。

## 4. 每个资产槽位的完成定义

一个槽位只有同时满足以下条件才可从 `graybox` 进入 `release_candidate`：

- `release_allowed=true` 且权利记录指向可复核的原创来源或商业许可。
- 正式资源路径存在，能够在固定构建中实例化。
- `fallback_policy=forbid` 时，资源缺失不会静默挂载灰盒。
- 相关办公室/城市行为回放仍通过，任务状态、碰撞、存档和事件时间轴不变。
- 相关视觉分段完成目标平台截图和人工逐项审阅，`visual_review.findings=[]`。
- 资源大小、加载时间、内存和帧时间通过目标设备门槛。

## 5. 产品基线确认后的实际顺序

1. 已写入并验证产品基线：Steam Windows、办公室垂直切片、原创写实中等细节。
2. 冻结首发范围，关闭非首发资产槽位的发布生产任务。
3. 建立角色、环境、动画、音频和标识规范，并保留原创来源记录。
4. 按第一批至第三批替换资产，每批都重新生成截图矩阵和事件证据。
5. 先完成 P0 候选接入和内部试玩，再由用户逐段进行人工视觉签收。
6. 完成目标设备、商店和发布 Go/No-Go 门禁。

当前仍不允许把候选资产直接当作成品发布；任何外部购买、委托、模型下载或商店素材制作，都必须补齐独立权利记录和用户确认。
